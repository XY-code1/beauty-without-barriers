# v0.3 规格：全妆工作台结构与眼线练习体验优化

- 日期：2026-09-24
- 开发分支：`codex/v0.3-makeup-workspace`
- 起点：GitHub `main` 的 `99ba250`，现有 v0.2 Demo
- 状态：工程实现已进入 Draft PR 交付；实际验证与真人待验收项见 `docs/v0.3-handoff.md`。以下保留批准时的规格要求。

## Problem Statement

化妆新手已经可以在 Demo 中查看单侧眼线参考轮廓，并通过分段关键帧检查获得实验性的方向反馈。但页面仍把摄像头、局部放大、参数、说明和按钮堆在同一长页面内。手机用户在实际操作中需要来回滚动，眼部周围的指示线、箭头和标签也容易相互干扰。

长期产品希望支持全妆辅助，当前页面结构却只围绕眼线展开。团队需要一个可继续接入其他妆容模块的共同基础，同时保留已跑通的眼线主流程，避免重复开发摄像头、MediaPipe 和相互不兼容的页面。

当前方向检查只有合成图及流程测试记录，尚不能确认真人眼线识别准确性。界面升级需要帮助用户理解参考路径、实际眼线候选和无法判断之间的区别，而不能制造已经实现全妆分析或可靠自动纠偏的印象。

## Solution

把产品整理为“妆容工作台 → 眼线准备 → 专注练习 → 结果检查 → 完成”的清晰体验。工作台展示可扩展的妆容分类，眼线是唯一可进入完整练习的模块；底妆、眉妆、眼影和唇妆标记为尚未开放，只提供简短状态说明。

手机练习时以目标眼睛的实时放大画面为主，配合一句动作提示和一个主要操作按钮。已有整体画面、参数微调与帮助按需展开。参考路径只强调当前操作分段，允许切换“跟着画”和“看效果”，并提供高对比显示及透明度控制。

沿用用户主动发起检查的方式，改善现有倒计时和采集流程，以短时多帧候选减少无效拍摄。检查后呈现本次照片、参考方向以及有真实检测依据的候选方向；无法可靠判断时显示原因和重拍入口。

本轮长期任务的可独立交付部分是前端实现、合成样本回归、页面验证和交付记录。真人样本验收与实体手机、新手试用单列，不以自动化通过代替。

## User Stories

1. 作为化妆新手，我希望打开产品后看到清楚的妆容分类，以便理解产品未来支持的练习范围。
2. 作为化妆新手，我希望立即分清哪些模块已经可用，以便不会进入只有空按钮的流程。
3. 作为化妆新手，我希望点击眼线后直接进入准备页面，以便快速开始已支持的练习。
4. 作为化妆新手，我希望了解当前只有一种自然眼线样式，以便对可选能力形成准确预期。
5. 作为化妆新手，我希望按自己的左右选择练习侧别，以便避免被镜像画面误导。
6. 作为化妆新手，我希望先查看形状、再按需调整长度和上扬程度，以便无需一次理解全部参数。
7. 作为化妆新手，我希望按钮使用“拍一张画前照片”等日常表达，以便知道接下来会发生什么。
8. 作为化妆新手，我希望开启摄像头前了解照片仅在当前会话内处理，以便决定是否开始拍摄。
9. 作为化妆新手，我希望在权限拒绝或模型加载失败时看到恢复入口，以便继续操作。
10. 作为化妆新手，我希望进入练习后看到放大的目标眼睛，以便看清落笔位置。
11. 作为化妆新手，我希望需要时切回整体画面，以便调整坐姿和镜头位置。
12. 作为化妆新手，我希望同一时刻只突出当前要画的一段，以便不会把其他段当成本次动作。
13. 作为化妆新手，我希望起终点说明和箭头不遮挡眼部，以便观察真实皮肤和笔触。
14. 作为化妆新手，我希望切换“跟着画”和“看效果”，以便分别理解操作方向和目标形状。
15. 作为看不清参考线的用户，我希望启用高对比显示和调整透明度，以便在当前光线下辨认指引。
16. 作为需要减少动态效果的用户，我希望系统尊重减少动画设置，以便不会被反复动效干扰。
17. 作为拿着眼线笔的用户，我希望当前提示和主要按钮同时可见，以便减少操作时的滚动。
18. 作为拿着眼线笔的用户，我希望点击检查后有清楚、可取消的倒计时，以便移开手并重新看向镜头。
19. 作为化妆新手，我希望系统在短时间内选择可用的清晰画面，以便减少刚眨眼就拍到废图的情况。
20. 作为化妆新手，我希望没有可用画面时得到具体重拍原因，以便知道需要调整什么。
21. 作为化妆新手，我希望暂停、人脸丢失或视频停滞时不再显示旧参考线，以便不会跟随过期位置落笔。
22. 作为化妆新手，我希望检查页面展示本次真实照片，以便确认系统分析的是哪次操作。
23. 作为化妆新手，我希望参考方向和检测方向拥有不同的线型及文字说明，以便不只依靠颜色理解差异。
24. 作为化妆新手，我希望只有检测可靠时才看到候选方向，以便不把没有依据的线条当成我的实际眼线。
25. 作为化妆新手，我希望能切换画前和画后照片，以便观察这次操作产生的变化。
26. 作为化妆新手，我希望获得与当前方向判断对应的调整建议，以便知道重拍或修改后如何继续。
27. 作为化妆新手，我希望由自己决定继续下一段，以便检查结果不会替我宣告操作完成。
28. 作为化妆新手，我希望无法判断时也能明确选择自行确认后继续，以便产品不会把我困在检查页面。
29. 作为化妆新手，我希望修改侧别或妆效目标后重新采集画前照片，以便不会拿旧目标评价新操作。
30. 作为化妆新手，我希望离开练习时知道是否会清除本次照片，以便避免误丢进度。
31. 作为关注隐私的用户，我希望确认结束或离开练习后停止摄像头并清除本次图像，以便拍摄不会持续到其他模块。
32. 作为键盘或辅助技术用户，我希望导航、弹窗和主要按钮有明确名称与焦点，以便可以完成同一条练习流程。
33. 作为手机用户，我希望页面旋转或放大文字后仍可操作，以便不会因为布局裁切而失去按钮。
34. 作为团队开发者，我希望其他妆容模块复用现有应用外壳和摄像头能力，以便减少重复开发。
35. 作为团队开发者，我希望共享坐标、图像和结果接口保持明确，以便合并模块时不会出现镜像、侧别或帧对应错误。
36. 作为项目验收者，我希望看到可复现的测试记录和截图，并区分合成数据与真人数据，以便判断实际完成程度。

## Implementation Decisions

- **技术基线**：继续使用 React、TypeScript、Vite、MediaPipe Face Landmarker、Canvas 2D 和 OpenCV.js。复用现有几何、检测、采集和会话状态逻辑，不引入另一套前端框架或视觉定位实现。仅在明确需要时拆分页面组件，不建设通用插件系统。
- **全妆工作台**：只增加导航、模块状态、简短说明和眼线入口。未开放模块不请求摄像头、不生成练习成绩、不伪造推荐。工作台与眼线模块使用同一套视觉样式。
- **页面切换**：采用轻量的浏览器地址片段导航，支持工作台和眼线入口的直接访问，以及浏览器前进、后退。眼线内部的准备、操作分段、检查与完成沿用同一会话状态；没有有效基准图时不得直接进入检查或完成态。
- **移动布局**：将准备与练习分开。练习状态收起首页宣传内容和参数设置；局部实时画面、当前一句动作提示与主要按钮优先占据首屏。整体画面按需切换；主操作区预留空间，不能遮住画面或内容。小屏、横屏与字体放大允许滚动，不通过截断内容或缩小文字强行塞进一屏。
- **视觉表达**：保留奶油白与绿色的整体方向，增强文字和控件对比度，统一按钮、图标及间距。普通正文与背景的设计验收目标为至少 4.5:1；主要触控目标至少 44 CSS 像素。所有必要信息同时用文字或线型表达，不只依赖颜色。
- **参考路径**：保留原方向轴与渐细轮廓，避免视觉造型修改导致现有方向检查失配。练习状态默认只强调当前操作分段，起终点文字放在不遮挡眼部的位置；准备与效果预览可展示完整轮廓。
- **显示偏好**：把已有模式命名为“跟着画”和“看效果”，增加普通/高对比以及透明度控制。它们只改变显示，不改变妆效目标、不清除基准图，也不进入图像分析输入。
- **采集体验**：复用已有确认与倒计时流程，改成清楚、可取消的三秒倒计时，不增加第二套入口。倒计时后在最多一秒内尝试采集至多五个不同的视频帧，跳过不满足已有几何与清晰度规则的候选，选择其中质量较好的一帧。采集数量和时间是实验参数，必须有上限；不能因为“必须选一张”而接受无效帧。
- **采集与状态一致性**：候选图像、眼部关键点、时间戳和目标版本成套保存。暂停、取消、离开模块、更换目标、页面进入后台时，中止待执行采集并使旧请求失效。不存在可用帧则提示重拍；关键点存在不作为无遮挡证明。
- **检查算法范围**：继续只评价眼尾方向，保留 10° 实验阈值和保守拒判。可以针对可复现的失败用例修复问题，但不通过放松阈值、读取虚拟轮廓或模拟答案制造通过结果。
- **检查结果可视化**：扩展现有评价结果，按需附带从真实候选像素拟合得到的线段位置及坐标系说明；端点取自候选在拟合方向上的实际范围。检查照片、参考路径和检测线段必须转换到同一局部坐标后显示，镜像只影响显示。不得仅凭一个角度在任意位置补画“实际眼线”。
- **无法判断的显示**：未通过可靠性条件时不显示确定的检测方向，不显示伪造分数；展示本次可用照片、具体原因和重拍入口。采集失败没有新照片时，不复用上次照片冒充本次结果。确定判断也标明只检查眼尾方向。
- **图像生命周期**：画前图、当前关键帧和检查可视化数据仅存在当前会话内，不上传、不进入浏览器持久化存储。检查与练习切换保留有效会话；确认结束、关闭摄像头或离开眼线模块时清除图像并停止媒体轨道。
- **摄像头生命周期**：同一眼线会话共用一个视频源和检测器。模式切换、放大/整体视图切换以及查看结果不能重复创建摄像头。离开时释放媒体轨道、检测器、动画循环和计时器；重新进入后由用户重新开启。
- **降级**：OpenCV 不可用时保留定位与操作指导，并明确说明本次分析不可用；摄影权限、模型、画面质量等失败均有明确恢复入口。未开放模块保持明确的不可用状态。
- **团队接口**：继续围绕妆效目标、视觉输出、关键帧、参考路径和评价结果协作。仅为结果证据增加必要字段，不把只适用于眼线的几何强制包装成所有妆容通用算法。

## Testing Decisions

- **主要测试入口**：沿用此前用户确认的完整浏览器操作流程，以工作台进入眼线、采集画前图、完成两次检查、主动推进步骤、退出或重试作为最高层验收入口。复用现有相机与定位测试替身，不另建平行测试框架。本轮已发出测试边界复核，默认继承既有验收约定。
- **什么是好测试**：验证用户可见行为与关键资源生命周期，不把组件拆法、CSS 类名或内部函数调用次数作为主要验收目标。新增测试应对应实际失败风险，避免仅复制实现。
- **导航与模块状态**：工作台可见，眼线可进入，其他模块清楚标为尚未开放；直接访问、浏览器前进后退、重复进入退出均有合理结果。缺失基准图或目标变化时不能跳过准备阶段。
- **完整练习回归**：复用已有正常操作、暂停恢复、重看、重试、重复提交、取消、侧别与目标变更测试，适配新的页面结构；检查结果不自动推进步骤。
- **采集回归**：通过现有测试替身构造清晰与模糊帧混合、无脸、全部不合格、视频重复帧及中途取消等情况。验证候选采集有时间上限，旧请求不会影响新会话，未得到可用帧时不会输出确定判断。
- **视觉证据回归**：在现有合成图方向测试上验证参考方向、候选拟合线与检查照片的对应关系。覆盖左右眼、镜像、旋转和缩放；未知结果不显示检测线；检测线端点不能由目标路径伪造。
- **图像隔离回归**：切换跟着画、效果预览、高对比、透明度、整体/局部视图和结果叠加后，分析输入仍是原始视频图像。沿用已有颜色转换容差，不以显示 Canvas 作为检测输入。
- **资源回归**：连续三轮进入、练习、退出，确认不残留旧画面、不重复持有摄像头或检测循环；倒计时、检查中退出及进入后台时不产生迟到结果。此项自动化资源测试不代替实体手机五轮运行。
- **算法回归**：继续运行已有 Vitest 几何、状态与真实 OpenCV 合成图测试，保留接近、偏高、偏低、未画、模糊和遮挡等样本。只有明确可复现的问题才扩展低层测试，且记录仍为合成数据。
- **页面视觉验收**：记录 390×844、360×800、844×390 和 1440×900 视口下的工作台、准备、练习、检查、失败与完成态。正常手机竖屏默认字号下，练习画面、当前简短提示和主按钮同时可见；横屏和放大字体时内容可达且无横向溢出。人工检查截图中的遮挡、层级和线条辨识度。
- **可访问操作**：键盘完成核心流程，焦点随页面和弹窗正确移动与恢复，按钮具有可理解名称，状态变化可感知；检查减少动画设置、文字放大和高对比显示。
- **统一检查**：单元/算法测试、页面测试、生产构建全部通过；测试替身不进入生产包。基线记录为 35 项单元/算法测试与 13 项页面测试，新版必须记录实际执行结果，不能沿用旧数字冒充新结果。
- **真人验收仍单列**：沿用 30 对清晰画前/画后样本（10 对调参、20 对独立验收，参与者分开），另加 10 组不可判断样本的计划。独立清晰验收至少 16 对给出判断，其中至少 90%正确；不可判断样本不输出确定方向。没有真实样本就记录未执行，不能用合成数据补足数量。
- **手机与新手验收仍单列**：主力手机连续五轮操作和三位新手试用需实际参与者及设备记录。无人值守执行不能独立完成的部分列入交接，不阻塞已经能验证的工程交付，也不宣称全部产品验收完成。

## Out of Scope

- 底妆、眉妆、眼影、唇妆的实际定位、路径生成或质量检查算法。
- 一夜内实现全妆推荐，或宣称已经帮助所有老年人、残障人士完成化妆。
- 自然语言妆效理解、大模型调用、联网产品推荐及成分分析。
- 连续笔尖追踪、手部自动触发、全程实时纠偏、双眼对称和眼线粗细/连续性评价。
- 自行训练视觉模型，或在没有真人证据时更换整条视觉技术路线。
- 后端、账号、数据库、用户画像、图片云存储、跨会话练习历史。
- 通用插件平台、复杂全局状态框架，或仅为未来模块预先实现一套重型架构。
- 自动升级依赖或浏览器工具、购买服务、对外正式部署、自动合并到主分支。
- 编造真人测试、手机性能或美妆准确率结果。

## Further Notes

### 建议的长程执行顺序

1. **全妆工作台与导航**：落地模块入口和眼线页面切换，保证已有练习主流程可达，验证离开和返回的会话边界。
2. **眼线练习 UI**：重排手机布局、调整指示线、统一日常文案，完成各主要页面的响应式截图检查。
3. **拍摄与检查体验**：完善现有倒计时、有限候选帧选择，以及有检测依据的照片对照与方向叠加。
4. **回归与问题修复**：运行现有及新增自动化，修复失败；对新的失败补充必要测试，避免无目的反复跑全量测试。
5. **交付**：更新功能状态、启动说明、测试证据和未完成项；在开发分支分阶段提交并推送，创建包含实际验证记录的 Draft PR，保留主分支供人工验收。

以上顺序是范围与依赖安排，不承诺在固定时间内完成。不得为填满运行时长而扩大需求。第一到第三部分未完成时，交付记录必须具体说明缺口。

### 工程完成条件

- 工作台与眼线的准备、练习、检查、完成页面均可使用，未开放模块状态准确。
- 手机竖屏核心练习可在同屏看到眼部画面、当前提示和主要按钮，参考标记不遮挡关键操作区域。
- 多帧采集、检查证据显示、取消与页面切换通过对应行为测试；未知结果保留清楚的失败解释。
- 原有完整流程、图像隔离、左右眼与目标变更规则不回退，统一自动化与构建通过。
- Draft PR 包含变更说明、可复现步骤、实际测试记录和合成/真实数据边界；真人验收未完成时明确保留待办。

### 执行中的停止与降级条件

- 没有真实样本时继续完成 UI、合成回归和测试工具；停止对真人准确率的无依据调参或承诺。
- 不能从候选像素可靠生成检测线时，保留照片与文字反馈，记录可视化未完成，不能用参考方向冒充检测方向。
- 摄像头或真机交互需要用户在场时，使用已隔离的自动化验证可测部分，并记录待人工执行步骤。
- 发现几何显示与方向检查冲突时，优先保留正确坐标与原始图隔离，不以视觉效果覆盖错误。
- 权限或外部服务阻塞时记录准确原因，不绕过认证；可以继续处理与该阻塞无关的本地工作。

### 可用作后续 Goal 的目标

> 在开发分支上完成本规格的 v0.3：实现面向全妆扩展的工作台与页面切换，完善单侧眼线的手机练习 UI、参考路径显示、有限多帧采集和有依据的检查结果可视化；保留原始图隔离与无法判断机制。完成自动化测试、响应式视觉检查和文档，提交并推送分支，创建 Draft PR，不合并主分支。将未能实际执行的真人样本、实体手机和新手验收清楚列入交接。
