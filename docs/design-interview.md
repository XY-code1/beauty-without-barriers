## 第一轮：当前可决定的事项

### Q1：检查请求的来源

情景：用户只画了一半，手移开去蘸取产品或短暂休息，画面恰好稳定。系统是否应该立即分析尚未完成的一段并反馈？

- 选项 A：用户点击“检查这一步”后，系统再等待合适画面并取帧。
- 选项 B：检测到手离开、画面满足采集条件后，系统自行启动检查，不需要用户明确请求。
- 助手建议：A。用户请求表达“现在想检查”，画面条件表达“现在可能可以拍摄”，两者应分开。手部接近信号仍可用于暂停采集或提示，并不要求把它解释成步骤完成。
- 用户选择：尚未收到。

### Q2：首个自动纠偏任务

候选：眼尾方向明显偏离参考、眼尾长度明显超出参考、目标段存在明显断线，或要求多项同时覆盖。

- 助手建议：先把“眼尾方向明显偏离参考”作为一个受控任务验证。方向是否真的可识别仍需样本测试；选择它是缩小任务范围，不是保证算法已经可行。
- 若方向任务被选中，反馈需要区分偏低、偏高、接近参考、无法判断；具体容忍范围和修正动作由后续样本及规则审核决定。
- 用户选择：尚未收到。

## 提议但尚未确认的术语

- 检查请求：用户或策略提出现在检查当前结果的意图。
- 可采集状态：当前画面满足一次结果采集要求的状态；不代表当前步骤已经完成或结果正确。
- 分段完成确认：明确推进操作步骤的确认；不等同于手离开眼区。

## 已核查的事实与推断边界

- Hand Landmarker 返回检测到的手的左右手信息及关键点，没有“手已离开眼区”或“操作完成”字段。[官方输出说明](https://ai.google.dev/edge/mediapipe/solutions/vision/hand_landmarker/web_js)
- 对手部粗略区域和目标眼部区域做距离或重叠计算，是应用层启发式。手未被检测到可能包含检测丢失，不能一律记成“手已离开”。
- Face Landmarker 返回面部关键点和可选的表情、变换矩阵，关键点存在不等于眼部像素清晰可见。[官方任务说明](https://ai.google.dev/edge/mediapipe/solutions/vision/face_landmarker)
- 部分不可见、低光、噪声和运动等会影响模型质量；可见性需要额外方法与测试，不能由“有关键点”直接推出。[Face Mesh V2 Model Card](https://storage.googleapis.com/mediapipe-assets/Model%20Card%20MediaPipe%20Face%20Mesh%20V2.pdf)
- “手离开 = 分段完成”是未经验证的业务意图推断。暂停、换工具或检测丢失均构成反例。即使采用自动触发策略，也要单独决定是否允许检查尚未完成的分段，不能让视觉事件替用户作这个选择。

本轮是文档与接口核查，未安装、运行或测试模型。引用对话中的 500 ms、30 FPS 等数值保留为示例参数，未作为已验证事实或冻结的验收标准。
